## Source/API notes and limitations hit during the run

- **ChEMBL**: `molecule.json` list endpoint returns `max_phase` as string
  `"4.0"` (detail endpoint returns a number); the gate coerces. Batch
  `molecule_chembl_id__in` used for the gate. DB = ChEMBL_37 (2026-05-01).
- **DrugCentral**: direct `drugcentral.org/api/drug/*` and
  `/drugcard/*/json` 404; implemented via `mychem.info` drugcentral block
  (approval rows are dict-or-list; normalized). 96/96 ids resolved.
- **STRING**: 12.5; `network` POST accepts ~450 ids/call; `required_score
  700` throughout; proximity routing universe capped at 450 nodes -
  distances are documented upper bounds.
- **Open Targets**: field names verified by live introspection
  (`drugAndClinicalCandidates`, `maximumClinicalStage`); ~108 clinical
  rows across MVA module.
- **DGIdb v5**: genes(names:) batched; ~1400 interactions for MVA module;
  many are code-named investigational agents (skipped by regex, counted).
- **openFDA**: label hit by generic/substance/brand name; `pediatric_use`
  clipped to 800 chars in output/fixtures.
- **SigCom LINCS**: canonical data host is
  `data-api.sigcom-lincs.k8s.maayanlab.cloud/v1/api/v1` (reached via 307
  redirects); protocol: metadata `/entities/find` -> data
  `/enrich/ranktwosided` -> metadata `/signatures/find`. Worked live;
  degrades gracefully with `lincs.status` recorded.
- **Benchmark misses are structural, reported honestly**: drugs acting
  downstream of the disease module never enter a target-overlap
  candidate space. If the team wants, widening the module (e.g.
  neighbour_limit 60->120 or adding phenotype-driven gene sets) would
  lift recall at the cost of noise - decision for the lead.
