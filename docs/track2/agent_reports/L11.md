## What was done

### 1. Pediatric-flag false negatives fixed (redteam m8 + lane task item 1)

Two independent bugs, both verified end-to-end against live openFDA
before fixing:

- **Wrong label could be selected.** The `limit=1` generic-name query
  returned whatever openFDA ranked first: `dasatinib anhydrous` 404'd
  entirely (no label at all), `metformin`/`metformin hydrochloride`
  matched the ZITUVIMET sitagliptin+metformin combination label, and
  `methylprednisolone` matched a 6-ingredient procedure-kit label whose
  8.4 text is about *bupivacaine* (producing a false POSITIVE flag and
  a false boxed warning).
- **Wrong section read.** The classifier scanned only
  `pediatric_use`; pediatric age floors routinely live in INDICATIONS
  AND USAGE (dasatinib "pediatric patients 1 year of age and older")
  or DOSAGE AND ADMINISTRATION (methenamine pediatric dosing,
  valproic acid "pediatric patients down to the age of 10 years").

Changes:

- `src/track2/sources.py` - `openfda_label` now (a) retries
  trailing salt/hydrate/ester form-word variants
  (`dasatinib anhydrous` -> `dasatinib`), (b) on a combination-product
  first hit issues one extra `limit=5` search and prefers the first
  single-ingredient label covering the drug (combo kept, and flagged
  `combo: true`, only when none exists), (c) preserves the original
  primary request so old fixtures replay identically. Match path is
  recorded in `meta.note`/`meta.combo`
  (`openfda_name_variants`, `openfda_is_combo`, `openfda_pick_single`).
- `src/track2/direction.py` - new `classify_pediatric(
  pediatric_text, indications_text="", dosage_text="")` scans all
  three sections sentence-by-sentence. In INDICATIONS/DOSAGE an
  affirmative age floor/band or weight threshold ("1 year of age and
  older", "pediatric patients >= 31 kg") counts only when a strict
  pediatric-population term is present - adult age floors like
  venetoclax's "in adults 75 years or older" do not qualify. In
  `pediatric_use` the old verb-positive rule is unchanged, so study-
  population age ranges ("25 pediatric patients, range 3-20 years")
  never count as indications. A positive sentence wins over negated
  statements elsewhere. Returns `(flag, evidence)` where evidence is
  `{section, text}` of the winning sentence; `pediatric_flag` keeps
  the old one-argument API.
- `src/track2/engine.py` - the label lookup now prefers the ChEMBL
  `pref_name` before collected names (fixes a real bug found in
  replay: glycerin's names set had union-merged "dextran sulfate
  sodium" onto CHEMBL692, and the alphabetical-first name attached a
  *dextran* label to the glycerin candidate). New emitted fields:
  `pediatric_flag_evidence`, `approval.fda_set_id`,
  `approval.combination_label`, `approval.openfda_match`.
- `src/track2/httpcache.py` - trim keeps
  `dosage_and_administration`; `indications_and_usage`/`dosage` stay
  verbatim (the previous convention for indications; only
  `pediatric_use` is clipped at the 800-char emitted-field bound).
  Engine clips classifier inputs at 4000 chars in both live and
  replay, so parity holds.

### 2. `merged` funnel counter (redteam m2)

`resolve_chembl` counts names resolving to a ChEMBL id another
candidate already holds; the name is union-merged into it. The funnel
now closes explicitly:

```
collected - dropped_over_cap
    == gated_in + gated_out_no_chembl + gated_out_phase
     + gated_out_withdrawn + gated_out_unresolved + merged
```

MVA run: 482 - 0 = 96 + 0 + 115 + 6 + 252 + **13**. Benchmark merges
per case: 19, 29, 1, 23, 14, 16, 6, 48, 6 (all nine cases reconcile).
